# L4 Device Certificate Logical Data Model

**Status:** Draft proposal

This document owns provider-neutral logical identities, state relationships, and transaction boundaries for the proposed DeviceLatent loop. It does not reserve migrations, prescribe physical indexes, activate wire contracts, or define delivery sequencing.

## Ownership boundaries

- `identity` owns certificate desired/reported state, certificate policy semantics, conditions, and the authorized `LocalOnly` inspection projection. This proposal defines no operator mutation action.
- `deviceloop` owns provider-neutral command and device-receipt state machines.
- the reconciliation runtime owns scheduling and attempt execution, not identity domain truth.
- PostgreSQL adapters persist the owners' ports under authenticated tenant scope.
- MQTT transports commands and facts; it is never an authoritative state store.
- external PKI owns certificate authorization, signing, and lifecycle; RSS stores only a sealed reference/receipt for an authorized public artifact.

## Logical identities

All tenant coordinates below are derived from authenticated scope at an application boundary. A caller-supplied body field cannot establish or override tenant or path device authority.

### DeviceCertificateDesiredState

Identity: `(tenant_id, device_id)`

| Field | Logical type | Rule |
|---|---|---|
| `generation` | positive generation | strictly increases through expected-generation CAS |
| `policy_hash` | SHA-256 digest | fingerprint of canonical authorized policy |
| `validity_seconds` | bounded duration | 300..=31,536,000 |
| `renew_before_seconds` | bounded duration | 60..=31,535,999 and strictly less than validity |
| `key_usages` | closed set | authorized usages only |
| `sans` | bounded values | inputs to external authorization, not self-authorizing claims |
| `created_at`, `updated_at` | server time | never ordered by device clock |

The desired row is the authoritative intent. Accepting it does not imply command receipt, certificate application, or convergence.

`validity_seconds` is `300..=31,536,000`. Draft-07 schemas carry each field's independent bounds; the domain's sealed policy constructor enforces the cross-field `renew_before_seconds < validity_seconds` relation and rejects a request before persistence.

### DevicePolicyOperation

Identity: `(tenant_id, device_id, idempotency_key)` where `idempotency_key` is a UUID from the PUT request.

The append-once operation stores the canonical request digest (expected generation plus canonical policy), accepted generation, and deterministic accepted response. Reusing the key with the same canonical digest returns that `200` response without another desired write or wake. Different input under the same key and an expected-generation conflict map to `409`; lookup outside authenticated tenant/path-device scope uses the same `404` as absence. Authenticated tenant and path device are part of the lookup scope and never come from the request body.

### DeviceCertificateReportedState

Identity: `(tenant_id, device_id)`

| Field | Logical type | Rule |
|---|---|---|
| `observed_generation` | positive generation | never decreases; zero is unrepresentable |
| `state_hash` | SHA-256 digest | canonical observed public state |
| `artifact_digest` | SHA-256 digest | public certificate-chain identity observed by the device |
| `expires_at` | device observation or absent | informative; not an ordering clock |
| `report_envelope_id` | stable opaque identity | idempotency link to the envelope, not a payload duplicate |
| `device_sequence` | nonnegative sequence | monotonic when the device supplies it |
| `device_observed_at` | device time or absent | never authoritative for ordering |
| `received_at` | server time | authoritative arrival time |

The initial reported state is represented only by absence of this row. A report event and the resulting row always carry a positive generation and required artifact digest; there is no generation-zero sentinel, nullable artifact compatibility form, or alternate initial-state variant. A report ahead of desired is a protocol violation. A report behind the reported high-water is retained only as receipt evidence and cannot move this state backward. #1893 proves the constructor/state transition rejects zero; #1895 proves the schema and generated emission seam reject a zero-valued event.

### DeviceCommand

Identity: `(tenant_id, command_envelope_id)`; scope link: `(tenant_id, device_id)`. `command_envelope_id` is generated by the sealed command-authoring seam and is not a payload field.

Required semantic coordinates:

- desired generation and positive fence epoch;
- opaque intent identity and policy digest;
- authorized artifact identity and certificate-chain digest;
- contract identity/version/schema identity supplied by the generated seam;
- deadline, optimistic version, and server timestamps.

State machine:

```text
queued -> published -> received -> applied
   |          |           |
   |          |           +-> rejected
   |          +-> timedOut
   +-> superseded
```

`received` means the device acknowledged the command. Only matching reported state can move the command to `applied`. `superseded`, `rejected`, `timedOut`, and `applied` are terminal for that command identity. Supersession is a fenced internal loop transition, not an operator action.

There is at most one current nonterminal intent for a device, generation, and intent identity. Once command storage exists, command authoring for a newer accepted desired generation supersedes older nonterminal intents in the same fenced command transaction; the desired storage transaction does not pretend to own command rows.

### DeviceIngressReceipt

Identity: `(tenant_id, ingress_envelope_id)`

This append-once record covers an ACK or report ingress outcome. It stores the closed outcome and reason, scoped device/command links, generation, epoch, optional device sequence, and server receive/commit times. It claims the stable envelope identity; event payloads do not duplicate that identity.

An ingress receipt may prove `committed`, `duplicate`, `stale`, or `rejected`. Only an outcome that passed authenticated scope, fencing, idempotency, and high-water checks may mutate current state. Public application receipts collapse unknown-command, unauthorized, and scope-mismatch failures to `NotAccepted`; a separately authorized internal audit record may retain the more specific reason.

### ApplicationReceipt

Identity: its generated outbox envelope identity. Correlation: `ingress_envelope_id`.

An application receipt is a publishable fact produced from the durable ingress transaction outcome. Its payload carries the ingress envelope correlation, closed outcome/reason, and committed server time. Publication occurs only after the transaction commits. A transport acknowledgement or an in-memory handler result cannot create this fact.

### DeviceReconcileCondition

Identity: `(tenant_id, device_id, condition_type)`

Condition type is one of `Ready`, `Reconciling`, `PendingDevice`, `Degraded`, `Quarantined`, or `Deleting`. Status is `True`, `False`, or `Unknown`. Reason is a closed value associated with the condition type. The record includes observed generation and server transition/probe times. Human-readable messages are rendered at an authorized edge; the durable state stores a closed message code without secrets or payloads.

`Ready=True` exactly means:

- desired state exists and no current `Quarantined` or `Deleting` condition is true;
- reported generation equals desired generation;
- reported state and artifact digest match the desired policy-bound artifact;
- authoritative server time is earlier than the artifact's typed `CertNotAfter`;
- the current `PgRevocationStore` lookup by typed `CertScope` and `CertSerial` returns not revoked;
- no newer nonterminal command exists.

A revocation-provider error or unavailable current answer fails closed: `Ready` is not true and the condition projection records a closed `Degraded` reason. The condition names `Quarantined` and `Deleting` remain closed projection values, but this proposal exposes no operator quarantine, unquarantine, or delete transition.

### ReconcileTarget and ReconcileAttempt

Target identity: `(tenant_id, reconciler_id, target_id)`.

The target contains durable next-run time, retry/failure streak, wake version, lease/fence epoch, last closed result label, and server transition times. An attempt captures its claimed generation and epoch. Process memory may optimize notification but cannot carry correctness state.

Exact-target wake advances durable target state. Periodic resynchronization remains capable of finding drift if notification is lost.

### CertificateRevocation

The existing `PgRevocationStore` model remains authoritative:

- identity: `(tenant_id, device_id, serial)`;
- lifecycle evidence includes `not_after`;
- repeated revoke is idempotent under that identity.

No second revocation entity, digest-keyed table, or independent reason model is introduced by this feature. External PKI remains responsible for certificate revocation publication and lifecycle services; RSS uses its existing revocation record within the current boundary.

### ExternalPkiProviderClosure

This sealed assembly-level capability proves that one selected external provider, its production configuration digest, and its provider-conformance evidence form an eligible production dependency. It is required by #1910 before runtime activation. It contains no tenant/device/generation authorization and cannot authorize an individual command.

### AuthorizedCertificateArtifact

This is a sealed capability/reference returned by an external PKI provider, not a certificate-authority record and never a private-key store.

| Field | Logical type | Rule |
|---|---|---|
| `artifact_id` | opaque ID | resolved only under authenticated tenant/device scope |
| `cert_scope` | sealed `CertScope` | authenticated tenant/device binding; cannot be supplied as payload authority |
| `desired_generation` | positive generation | exact desired match |
| `cert_serial` | sealed `CertSerial` | exact serial coordinate for the existing revocation store |
| `public_key_digest` | SHA-256 digest | binds the enrolled device key |
| `certificate_chain_digest` | SHA-256 digest | identifies the public artifact |
| `policy_hash` | SHA-256 digest | binds authorized SAN, key usage, and validity policy |
| `cert_not_after` | sealed `CertNotAfter` | provider-authoritative expiry used with server time |

The sealed internal receipt makes `CertScope`, `CertSerial`, and `CertNotAfter` available to RSS readiness and revocation checks without making them caller-forgeable command fields. The artifact is issued/resolved for one command-authoring decision. Device commands still carry only `artifact_id` and `certificate_chain_digest`; they never carry a private key, raw CSR, serial authorization, or material not authorized by this capability. A deterministic simulator may return a non-production artifact type, but that type can satisfy neither `AuthorizedCertificateArtifact` nor `ExternalPkiProviderClosure` production dependencies.

## State relationships

```text
DesiredState (generation N)
  -> ReconcileTarget/Attempt (generation N, epoch E)
  -> DeviceCommand (generation N, epoch E, artifact reference)
  -> ACK ingress receipt (command received/rejected)
  -> Report ingress receipt (observed generation/state)
  -> ApplicationReceipt (post-commit outcome)
  -> Conditions / Ready only when report matches current desired
```

Relationships obey these rules:

1. desired generation and reported generation are monotonic high-water values;
2. every state-changing command or fact is checked against authenticated scope, generation, and epoch;
3. ACK and report are different facts and advance different state;
4. stale facts may append evidence but cannot mutate high-water state;
5. readiness additionally requires an unexpired artifact and a current not-revoked result; provider failure is non-ready and degraded;
6. provider identities are not interchangeable between simulator and production;
7. operator access in this contract set is read-only; automatic repair and supersession are internal transitions.

## Transaction boundaries

### Desired storage and policy validation

```text
authenticate tenant and authorize path device/action
-> validate independent duration bounds and sealed cross-field policy relation
-> enforce desired monotonicity, uniqueness, FORCE RLS and grants
```

This is the #1896 storage/domain-constraint surface. It does not own a scheduler wake or a command supersede transaction.

### Desired update and wake

```text
authenticate tenant and authorize path device/action
-> claim idempotency key and compare canonical request digest
-> compare-and-swap desired generation
-> make the reconcile target durably due and advance wake version
-> persist the deterministic accepted operation result
-> commit
-> optionally notify the scheduler
```

Any compare-and-swap conflict has zero writes across the entire unit. An identical idempotency replay returns the stored accepted result without writes. This transaction is introduced by #1898 after the desired and scheduling stores are available.

### Reconcile action

```text
claim and verify target lease/generation/epoch
-> resolve a correctly typed authorized artifact capability
-> append action outcome
-> supersede obsolete nonterminal commands for older desired generations
-> create or claim the canonical device command
-> append the typed command outbox fact
-> commit
```

A lost lease, stale generation, stale epoch, or production-ineligible artifact prevents a current command from being emitted. #1900 owns this fenced supersede/command transaction after command storage exists.

### Device ingress

```text
authenticate transport scope and claim the stable envelope identity
-> validate device/command/generation/epoch and device-sequence high-water
-> append the deterministic ingress outcome
-> conditionally update command or reported state with compare-and-swap
-> update conditions and durably wake the target
-> persist the application-receipt outbox fact
-> commit
-> publish the application receipt
```

The transaction owns both the mutation and the receipt fact. A crash before commit yields no application receipt; redelivery re-enters through the same stable envelope identity.

## Direct replacement

The current `identity.reconcile-loop` contract is an empty draft with no production rows or external consumers. Its implementation is replaced directly by this proposal's contract identities. There is no compatibility alias, shim, dual reader, dual write, or backfill model.
