# CI 可靠性修复与历史边界

#2355承接#2329、#2316及最近CI会话的测试可靠性修复；#2356单独优化affected选择。
修改测试预算、隔离资源identity和修复编译不属于性能优化。诊断缺失可以修复，但不能据此
声称尚未定位的Docker映射故障已根治。

## 容器 identity 与 readiness

testkit不再将稳定DNS名设置为daemon全局容器名称。testcontainers 0.27.3无network alias
构造API；PG/RabbitMQ/MinIO先由既有runtime创建并保留默认bridge/端口发布，再通过有界
`docker network connect --alias`附着到调用方独立网络，成功后返回fixture。Docker拥有全局
identity，NetworkAttachment只拥有network及其局部DNS。失败时仅释放本次容器，launcher
仍按本run label兜底清理；不删除其它run的资源，也不升级依赖或断开重连默认网络。

PG最终ready与初始化临时server不同；对照upstream Postgres模块等待stdout和stderr两阶段
ready，再查询原容器端口。最终PortNotExposed仍失败；清理前仅投影running、exit code、
OOM、restarting和configured/published端口绑定数量。采集有5秒预算，失败标注unavailable/
failed/timeout，保留原错误；不采集环境、凭据、原始State.Error、host地址或日志正文。

真实回归在现有postgres-integration carrier中并发创建两个相同DNS的独立网络fixture，
验证宿主映射端口SQL/TLS、网络内DNS与证书SAN、清理一方后另一方继续可用、失败附着不会
影响存活fixture。原代码确定性Docker409；修复后用同一binary经两个独立launcher同时
执行，三批共六次通过。首次新实现测试仍出现PortNotExposed，且当时诊断模板不处理nil，
报告inspect-failed；模板已修并在真实未启动容器上验证nil映射。该失败保留，#2316根因
追踪保持开放，不能把后续通过当根治。

## 测试握手与预算

orphan测试的child用原子ready文件报告自身PID，父测试据此清理；故意将诊断metadata.pid
置空后，继承内核锁仍须阻止第二个run入槽。不能从ready推导父进程metadata已写完。
模拟SemVer installer的外层测试预算为60秒以包含冷启动/解包/校验，生产下载和重试策略
不变。AMQP关闭顺序证明在shutdown预算前计入有界broker观察时间，保留其它zero/5秒
关闭测试；不重置生产deadline、不添加测试自动重试。

launcher归档冷启动的60秒测试预算已在PR#951落地；共享JSONL并发写坏及诊断影响正式
result的问题已在PR#944修复，此处复用既有回归，不重做结果或缓存系统。

## 构建基线修复

当前develop=e92127023还存在迁移遗留：PG relay probe引用不存在的AbsoluteDeadline；
examples provider/memory引用旧Clock、MonotonicInstant/AbsoluteDeadline。直接适配
request-context::{Clock,Deadline,ExecutionTimer}和OperationDeadline::from_cutoff，并在
memory feature显式引入request-context；无兼容alias。数据保护示例同步使用现有
ProtectionContext::new，仅验证坐标形状，不赋予认证/授权含义。rustc失败作为红灯证据，实际
provider及独立memory/producer/consumer消费者负责证明feature闭包与运行语义。

## 历史来源与开源对照

固定基线5b63e10a1b396b0ff70b7d1e6e55db296cd7a891的target-pool.py使用PID租约和存活探测；
当前ci-run.py使用继承内核锁，PID仅诊断。不能拿旧PID owner规则测试新锁实现。
历史基线的testkit `env_or_*` 默认每次自起容器，guard活到测试结束；RabbitMQ只在同一
fixture内复用vhost，不跨nextest进程共享。旧rss-rust-job.yml给integration group注入
scope/shard/partition/service四维标签，integration-services.sh先采集现场再按标签复核清理。
旧test-affected与postgres/transport/runtime/artifact runner各自构建xtask并直接nextest执行，
可能重复编译，以typed shard、JUnit/sidecar保存执行事实。

当前build job仅生成一次nextest archive，以inventory/manifest/digest证明五组不漏不重；
执行runner消费同一archive，真实provider仍在各runner启动。AMQP/Kafka/MQTT由group级
launcher写私有descriptor并跨该组测试进程共享；PG/Redis/MinIO和exclusive场景仍各自持有。
正常Drop与最终run UUID label扫尾分别负责正常/异常清理，child与cleanup结果都保留。
这部分archive、共享和cache已经是已落地优化，不在#2356重复实施。
选择器历史对照和减少无关测试的收益见#2356文档，不恢复旧xtask产品T3/控制平面。
