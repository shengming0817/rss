# RuntimeInventory 运维说明

三个受支持 assembly 都只在 Admin listener 提供 `GET /api/v1/runtime/inventory`。该契约显式声明为 global/operator resource：inventory 描述整个进程，不从 ambient tenant 或路径参数推导资源范围；这只说明被读取的资源没有 tenant owner，并不取消调用主体与授权 grant 的 tenant 边界。runtime 与 identityaudit 的 RSS access verifier 仍只接受带有效 tenant 和 current AuthGrant 的 `User`，随后 Identity `ContractAuthorizer` 必须在该 tenant 的 durable role binding 中精确找到 `runtime:inventory:read`；缺 grant 返回 403，绝不为 RSS token 引入 Admin/SuperAdmin profile。settingsonly 继续使用 federated verifier 与独立 exact authorizer，仅允许 Admin 或无 tenant 的 SuperAdmin。Primary、Internal 与 Health listener 均不挂载该契约。

成功响应公开当前 assembly、RuntimePlan、DeploymentPlan fingerprints，启动制品身份、实际绑定 listener、provider posture 与 placement。它不包含 secret、token、tenant 数据或自由 metadata。provider posture 在每次请求时从当前 HealthReporter 重新聚合；预期 probe 缺失或 Unhealthy 均返回 `unavailable`。Remote placement 的 `readiness` 同样是必填的当前观测值，每次请求从生产 domain transport 的 live readiness handle 采样，不复用启动期 endpoint resolution 占位。

进程只在启动快照读取一次 `RSS_BUILD_SOURCE_SHA` 与 `RSS_BUILD_IMAGE_DIGEST`。前者必须是 40 位小写十六进制，属于部署方声明；运行时不声称独立证明 OCI 来源或 same-head。后者必须是 `sha256:` 加 64 位小写十六进制，并与绑定 DeploymentPlan workload image digest 完全一致。缺失、格式错误或摘要不符都会在绑定 socket 前终止启动。

所有 listener 成功 bind 后、任何 serve 激活前，组合根一次性发布 inventory。发布会把 RuntimePlan 的 listener identity、DeploymentPlan 的 service/probe 端口与实际绑定 endpoint 做 exact join，任一端口漂移都会在 serve 前 fail closed。发布前请求返回可重试的 provider-unavailable 503 envelope；认证失败返回 401，授权失败返回 403，持久审计失败返回 500，且这些失败均不会执行 inventory handler。授权结果写入现有 PostgreSQL auth audit sink，不使用 tracing-only 替代。

发布与制品轮换必须原子进行：同一 rollout 中的 binary/image、AssemblyLock、RuntimePlan、DeploymentPlan 和两个 `RSS_BUILD_*` 值必须属于同一制品集合。回滚时也必须整体回滚，禁止只回滚镜像或只恢复计划文件；否则 pre-bind identity guard 会拒绝启动。先确认新实例 inventory 的三项 fingerprint、image digest、listener endpoints 与 placement，再扩大流量。
