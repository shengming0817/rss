# RuntimeInventory 运维说明

三个受支持 assembly 都只在 Admin listener 提供 `GET /api/v1/runtime/inventory`。该契约显式声明为 global/operator resource：inventory 描述整个进程，不从 ambient tenant 或路径参数推导资源范围；这只说明被读取的资源没有 tenant owner，并不取消调用主体与授权 grant 的 tenant 边界。runtime 与 identityaudit 的 RSS access verifier 仍只接受带有效 tenant 和 current AuthGrant 的 `User`，随后 Identity `ContractAuthorizer` 必须在该 tenant 的 durable role binding 中精确找到 `runtime:inventory:read`；缺 grant 返回 403，绝不为 RSS token 引入 Admin/SuperAdmin profile。settingsonly 继续使用 federated verifier 与独立 exact authorizer，仅允许 Admin 或无 tenant 的 SuperAdmin。Primary、Internal 与 Health listener 均不挂载该契约。

成功响应公开当前 assembly 与 RuntimePlan fingerprints、实际绑定 listener、provider posture、placement，以及 sealed workflow plan 中的 `activatedWorkflows`。该数组只包含启用的 Projection/Saga，按 workflow ID 稳定排序；disabled/omitted 不输出，且不重复 capability 或 health。启动方同时提供 source revision 与不可变 image digest 时，响应以闭合的 `buildMetadata` 成对报告；缺一、格式错误或大小写错误均拒绝启动输入。该字段是 launch-supplied declaration，不是进程对 OCI manifest 或 SLSA provenance 的自证，也不参与 RuntimePlan、workload 或 deployment fingerprint。响应不包含 secret、token、tenant 数据、外部调度身份或自由 metadata。construction-only provider 没有动态健康证据，固定报告 `unobserved`，不得作为 readiness 放行依据；它与已观测失败的 `unavailable` 明确区分。`listener-pdp` receipt 同时拥有所选认证 profile 的 JWKS managed resource 与 readiness probe；provider posture 在每次请求时只从该 receipt 声明的非空 probe 集重新聚合，取最差状态，预期 probe 缺失、Unhealthy 或未知状态均返回 `unavailable`，其他 provider 不继承该状态。Remote placement 的 `readiness` 同样是必填的当前观测值，每次请求从 domain transport 的 live owned-readiness handle 采样：它只表示本地 outbound SPIFFE material 当前健康且 current SVID 与配置的 local SPIFFE ID 精确一致，不表示 peer 可达性；SVID 轮换到其它有效 ID 也会 fail-closed。启动 seed 使用 `mtls-source-unavailable` fail-closed 占位，live sampler 发布后只产生 `ready` 或 `mtls-source-unavailable`。

`schemaVersion: 2` 将 projection workflow 分成闭合变体：`capture-only` 只报告静态定义；`shadow` / `active`
必须同时报告 plan-bound `targetGeneration` 和 live `workerStatus`。worker 状态来自同一进程 worker 的完整 tenant
sweep，在每次 inventory read 时重新采样。generation 只报告 `none`、单一 `uniform` 或 `mixed`；lag 先按 tenant
计算 source high-water 与 checkpoint 的差，再取最大值。状态不会公开 tenant ID、tenant 数组、原始 LSN、错误文本
或精确坐标。逐 tenant 精确状态继续使用 Runtime-owned `rss projections status`。

`starting`、`unavailable` 与 fatal `stopped` 不携带可能过期的 generation/lag。完整 sweep 才发布 generation/lag；
tenant retryable 与 durable quarantine 使用闭合 reason posture，多个不同 reason 收敛为 `mixed`。durable quarantine
reason 从 worker-owned observation function 恢复，因此进程重启不会把 quarantine 降级为布尔值；正常 cancellation
不伪装成 fatal。fatal `stopped` 是进程内终态，后续 sweep publication 不能覆盖。

所有 listener 成功 bind 后、任何 serve 激活前，组合根一次性发布 inventory。发布会将 RuntimePlan 的 listener identity/auth 与实际绑定 endpoint 结合，不读取外部 service/probe 投影。发布前请求返回可重试的 provider-unavailable 503 envelope；认证失败返回 401，授权失败返回 403，持久审计失败返回 500，且这些失败均不会执行 inventory handler。授权结果写入现有 PostgreSQL auth audit sink，不使用 tracing-only 替代。

reader invariant 或 wire projection 失败统一返回不可重试且无 details 的 500。服务端 ERROR 只记录 contract id、固定 error code、request id 与闭合的 `observation.*` / `projection.*` stage，便于用响应 `requestId` 关联故障位置；日志不包含 inventory runtime value、内部属性或自由文本错误。

外部 delivery 系统负责校验 image digest、source revision、provenance 与 rollout 原子性，并通过 `RSS_BUILD_SOURCE_REVISION` / `RSS_DECLARED_IMAGE_DIGEST` 将已选择 artifact 的声明交给进程报告；应用 inventory 不把声明冒充为验证 receipt。扩大流量前，先由外部系统核验 artifact，再确认新实例报告的 build metadata、assembly/RuntimePlan fingerprints、listener endpoints、provider posture 与 placement readiness。

placement projection 决定实际 listener membership 与 active provider posture：Remote domain 的本地 listener 和 domain-owned provider 必须完全缺席，不能以 `unobserved` 占位。operator 放流前需要分别核验 source 的 outbound SVID readiness 与 peer 自身的 inventory/fingerprint/readiness。

`runtime.inventory@v1` 已 intentional breaking 地切换为 `schemaVersion: 2`，不提供旧 DTO、alias、shim、双读或
双写。部署不支持新旧 binary 或 inventory consumer 混跑：先 drain 全部旧实例，同步升级 consumer，再启动新实例并
确认其接受 projection worker 闭合状态。回滚同样必须先完整 drain，避免 schemaVersion 1 consumer 读取版本 2 响应。
