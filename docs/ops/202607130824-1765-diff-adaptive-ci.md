# Typed Diff-Adaptive CI 运行手册（#1765、#1813、#1887）

## 当前状态

GitHub Actions 的普通 PR 路径已收敛为 `selector` 加固定 `check`、`test-affected`、
`integration-critical`，最后由 result-only `gate` 聚合。三个执行 Job 始终存在；selector 只输出规范
`SelectionPlan`，不通过增删 Job 表达影响范围。`test-affected` 还始终生产 LocalOnly required evidence，
其结果随该 Job 成败，不形成额外 Job 或第二 verdict。

Azure 仍是当前 forge。GitHub workflow、required check 与 Azure policy 是不同状态；迁移和 branch protection
必须按实际平台配置验证，不能从仓库文件存在性推断。

## PrComplete 与 ReleaseCheck

`PrComplete` 是普通 PR 的保守上限。它仍只运行固定 PR 图内的 check、affected component test 与 critical
integration，不运行 workspace coverage、audit、全部 integration shard、发布或其它完整事件成员。

`ReleaseCheck` 是所有 canonical owner 的并集并应用 typed subsumption，只属于 develop、nightly、release
或显式 `cargo xtask ci full`。selector 的不确定性、高影响根或紧急保守选择不得把 PR 事件改造成
`ReleaseCheck`。

## SelectionPlan 与影响闭包

`ImpactSet` 记录直接 package 影响、反向依赖闭包、稳定 `IntegrationUnitId`、治理路径以及
unknown/high-impact/failure 状态。selector 从同一模型生成规范 `SelectionPlan`：

- 普通 rename/copy 按 delete + add 分析；两端都可分类时保持选择性。
- contract rename 涉及 owner/subscriber 映射，保守升级 `PrComplete`。
- mixed known + unknown 保留 unknown trace，但继续运行已知 package 和 integration unit 的定向选择。
- unknown-only、diff/metadata/merge-base/策略分析失败和真正高影响根升级 `PrComplete`。
- BASIS/共享基础 crate 使用 reverse dependency closure；闭包可证明时仍是 selective，而不是无条件完整。

规范 plan 明确记录选择模式、原因、unknown trace、affected package、reverse closure 与稳定 integration unit
ID。三个执行 Job只消费各自字段；空选择必须以显式成功结束，不能跳过 Job。

## 固定 Job 入口

```bash
cargo xtask ci run --job check --selection '<canonical SelectionPlan JSON>'
cargo xtask ci run --job test-affected --selection '<canonical SelectionPlan JSON>'
cargo xtask ci run --job integration-critical --selection '<canonical SelectionPlan JSON>'
```

`--selection` 只接受 selector 生成的 canonical `SelectionPlan` JSON。未知、缺失、重复字段、自由 filter、
错误 profile 或 selection/unit ID 不一致均 fail-closed。integration 的资源、batch、nextest filter 和 replay
全部从稳定 unit ID 投影。

gate 在 `always()` 下读取 `check`、`test-affected`、`integration-critical` 的最终状态。任一 failure、cancelled
或非预期 skipped 都失败；它不下载或解释 artifact，也不验证附加运行报告。日志、JUnit 与 nextest replay
只用于诊断，不能改变 gate verdict。

## Required evidence 与独立诊断

LocalOnly 运行报告由普通 PR 固定图内的 `test-affected` producer 拥有。以下命令是该 producer 的唯一公开
直接入口，可用于 Azure 窄 validation 或人工复现；供应链 audit 才是固定 PR 图外的独立诊断：

```bash
cargo xtask ci localonly-evidence --output target/localonly-execution.json
cargo xtask ci audit
```

前者只在 exact nextest suite 成功且 active/source/executed 集合相等后原子发布报告。远端
`test-affected` 通过同一私有 producer 始终执行这项 required evidence；gate 只消费 Job result，不下载报告。
后者用于定时或显式供应链检查，普通 PR 的 `PrComplete` 不自动调用 audit。

## 本地 10 分钟预算与重型任务边界

`make ci CI_BASE=<remote>/develop` 是本地 PR 收尾入口，预算 600 秒。它运行 `meta`、反向依赖 check、直接
受影响 package test/clippy 和定向治理自测；unknown 混合影响留痕并继续已知选择，分析失败直接报错。
成功 stage 可写入当前 worktree/branch ledger；`--fresh` 从头运行。

以下任务只属于 develop/nightly/release 或显式 `make ci-full`，不得追加到每个本地 PR 或远端
`PrComplete`：

- workspace all-features build/clippy 与 workspace coverage；
- 全部 integration compile/live shard；
- public-api、dylint、完整 deny/audit；
- fault/recovery、performance/soak 与发布相关验证。

coverage 的完整事件边界见
[`202607260602-coverage-scope.md`](./202607260602-coverage-scope.md)。固定拓扑与 profile 所有权见
[`202606231530-001-ci-lane.md`](./202606231530-001-ci-lane.md)。

## 排障

1. selector 失败：查看闭合错误码和 subject；PR 应进入 `PrComplete`，而不是放大为 `ReleaseCheck`。
2. `test-affected` 失败：核对 affected package 与 reverse closure，再以同一 canonical JSON 重放。
3. `integration-critical` 失败：按 selection 中的稳定 unit ID 查 catalog、资源和 nextest sidecar。
4. gate 失败：只比较三个执行 Job 的最终状态；不要用 artifact 或手工摘要覆盖失败结果。
5. 固定 Job 缺失或被条件跳过：视为 workflow topology drift，由结构化 YAML 守卫修复。
