# Typed Diff-Adaptive CI Shadow 运行手册（#1765）

## 当前状态

GitHub Actions 的 `CI` workflow 正常路径已收敛为 `ci-plan → execute(dynamic matrix) → ci-gate`；唯一例外是
planner 失败时的定时 Audit 兜底。策略文件
`.config/ci-impact.toml` 当前固定 `mode = "shadow"`：planner 仍计算推荐 job 集，但每个 PR、develop push、
`feature/**`、`fix/**`、`codex/**` push、schedule 与 workflow dispatch 都执行闭合的 14-job catalog。分支
push 是 GitHub PR mirror 完成前的 Shadow 样本入口；激活 adaptive 时再随真实入口迁移一并收口。此阶段只
收集证据，不关闭 #1765。

Azure 仍是当前 forge；人工 mirror、GitHub PR 迁移和 branch protection 不属于本次代码变更。迁移完成前，
`ci-gate` 只是可观测 check，不得声称已经成为 required check。

## 计划与故障语义

- PR 使用 base/head 三点 diff；merge-base、NUL name-status、Cargo resolve graph、contract owner/subscriber 与
  integration execution unit 共同生成计划。
- rename/copy、shallow history、非 UTF-8、未知路径、策略/metadata/diff 失败均选择全量。
- `mandatory-full` 表示 event、Shadow、显式 override 或高影响策略要求全量；`fallback-full` 仅表示输入不确定。
- `RSS_CI_FORCE_FULL=true` 是唯一紧急回滚开关；非法值同样 fail-safe 到 `fallback-full`。
- `policyVersion` 绑定策略文件、独立行为 golden、`CiJobKey`、Integration shard 与路径规则；行为与 golden
  不一致会令测试失败，`planDigest` 绑定本次完整计划。
- fallback 计划携带封闭的 stage、稳定错误码、可选仓库相对 subject 与操作建议；原始错误、绝对路径和
  控制字符不会进入计划或 step summary。

`ci-gate` 只在 planner 与 matrix 聚合均为 success，且 evidence v4 的 artifact/job/source revision/plan digest/
run identity 与计划执行集合完全相等时通过。failed、cancelled、skipped、缺失、重复或额外回执均失败。

workflow concurrency 按 event type 与 PR/ref 隔离；schedule 不与 develop push 共享 pending slot，且仍只有 PR
run 会取消同组旧运行。正常 schedule 通过 typed full matrix 执行 Audit；若 planner 或 typed plan artifact
上传失败，统一 `ci.yml` 内的 `scheduled-audit-fallback` 仍直接执行同一个 `cargo xtask audit` 计划。兜底不
伪造 plan/evidence，`ci-gate` 仍因 planner failure 失败，因此既保住每日供应链审计，也不会把故障运行误报为绿。

## Shadow 样本与激活门

在人工 mirror 的 GitHub PR 上收集 5–10 次代表性运行，至少覆盖：纯文档、普通 Rust、adapter/integration、
contract/generated、全量 fallback。每次从 `ci-impact-plan-<run>-<attempt>` artifact 与 Job Summary 记录：

- 推荐 job 数、实际 14-job 数和 fallback 原因；
- 推荐集合之外是否出现真实失败；
- 回执集合是否完整，`ci-gate` 是否存在假通过；
- runner wall time、CPU time、预计节省 CPU time、peak RSS、磁盘和 cache 诊断。

只有零推荐漏检、零 gate 假通过、回执完全准确且所有 fallback 可解释时，才创建单独激活 PR，把 mode 改为
`adaptive`。激活前必须已将 GitHub PR 设为真实入口，并人工把稳定 `ci-gate` 配成 required check；激活 PR
使用 `Closes #1765`，本 Shadow PR 只使用 `Refs #1765`。
