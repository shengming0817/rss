# CI 文档变更的选择边界

`hack/ci-impact.py` 是 package 选择唯一入口。已识别文档不贡献 package seed；与 Rust 代码
混合提交时，仍按代码 owner 的完整反向依赖闭包选择。纯文档变更为空 package 集。

协作技能说明仅按 `.claude/skills/`、`.codex/skills/` 前缀与 `.md` 后缀同时识别；同目录
脚本、配置或其它未知文件继续全量。Cargo/global 输入优先于文档识别；rename/copy、未知
删除、分析异常维持 fail-full。没有扩大到整个 `.claude`/`.codex` 或 `hack` 目录。

这减少无关验证，不允许忽略选中测试失败，也不改变 fixture 并发、timeout、重试、coverage
门槛或正式结果。#2329/#2316 的缺陷修复由 #2355 承接，不能靠少跑测试关闭。

## 历史对照

固定历史基线 `5b63e10a1b396b0ff70b7d1e6e55db296cd7a891` 的
`xtask/src/ci_impact.rs`（`classify_manifest_entry` / `try_impact_entries`）逐项处理：文档
直接完成分类，package 另行累积，因此 mixed docs+crate 不进入 unknown paths。
当时 `.config/ci-impact.toml` 还将整个 `.codex/` 作为 external 路径；本次没有恢复这类宽排除。

`04da53e81`（PR #903）以 package-only selector 替换旧 xtask 平台；当前变更只恢复
文档中性这一行为。随后 `e7ac9750f` 恢复六槽 target/sccache、`deaa0a5f` 引入一次
nextest archive 构建及共享 fixture、`58d67c430` 解耦诊断与正式结果；这些机制保持原 owner。

## 验证及收益

黑盒临时 Git/Cargo workspace 测试覆盖：纯文档、两种技能前缀、文档混合源码/删除、
normal/dev/build/optional 反向依赖、全局输入、未知路径、rename/copy 和异常回退。

修改前新用例失败：skills Markdown 与 mixed docs+crate 都 full=true；修改后 17 项
`python3 -m unittest hack.tests.test_ci_impact` 通过。合成 core+docs case 从 full workspace
缩小到 core 与五个真实消费者，不再选 other/other-integration；不是按文件名硬编码包清单。

历史 PR #950 的六份说明变更可用固定 revision pair `06e449bcd..99d214219` 对照选择输出。
收益以避免全 workspace/provider 执行和保持实际依赖闭包为依据，不宣称未经测量的wall-clock
加速倍数。本PR修改selector自身仍触发global-input full验证。
