# RSS server 容器镜像与部署

> #1134（area-tooling）。本文档是 `bins/server` 多阶段 Dockerfile + 最小运行镜像的构建 / 运行 / 验收 /
> 编排契约。镜像构建逻辑单源 = 仓库根 `Dockerfile`；演示栈 = `deploy/docker-compose.yml`；冒烟 acceptance
> harness = `deploy/smoke.sh`（`make docker-smoke`）。必填环境变量单源 = `assemblies/runtime/src/lib.rs`
> 的 `build_*` fail-fast 读取点。

## 背景

RSS 此前零部署产物（无 Dockerfile / compose / k8s）。本文档随第一份容器化交付单元落地：把
`bins/server`（薄入口 → `runtime::run()`）编进**非 root、只读 rootfs 友好、distroless** 的最小运行镜像，
并给出可机器闭环验收的演示栈（`docker run → /readyz 200`）。

> **scaffold 阶段声明**：当前 runtime compose `SettingsDomain` + `AuditDomain`。对外**匿名可验收面**是
> `/health/v1/*`（healthz/readyz/**metrics**，Health listener 8083，`AuthScheme::NoAuth`）；此外 `AuditDomain` 在
> **Admin listener（8082）**注册 `GET /api/v1/audit/entries`（按 Admin listener 鉴权保护，非匿名可达）。其余业务
> 路由待 #1017 伞 / 各域 wire PR。
>
> **匿名 metrics 面的网络边界（部署契约，非仅代码约定）**：`/health/v1/metrics` 与 healthz/readyz 同挂
> `NoAuth` Health listener（`diport::MetricsExporter` 规约要求 scrape 面仅内部网络可达）——**必须仅 loopback /
> cluster-internal 暴露，绝不作公网 ingress 入口**。演示栈已在 `deploy/docker-compose.yml` 把 8083 绑 `127.0.0.1`
> 落实该边界；生产 k8s 经 Health listener 的 `ClusterIP` Service + Prometheus cluster-internal scrape 保持同语义（见 §可观测性导出）。
> 镜像真实启动、连 PG、跑迁移、serve readyz——容器化交付链与健康闭环**现在即完整可验**；业务端点随后续域 PR
> 进入同一镜像，Dockerfile 不变。

## 镜像结构（多阶段 cargo-chef + distroless）

`Dockerfile` 4 阶段（ref: cargo-chef README.md / ref: distroless examples/rust/Dockerfile）：

| 阶段 | 基底 | 职责 |
|------|------|------|
| `chef` | `rust:1.96.0-bookworm` | 钉版工具链（= `rust-toolchain.toml` channel）+ `cargo-chef`（钉 0.1.77；须 ≥0.1.71 支持 edition 2024）。 |
| `planner` | `chef` | `cargo chef prepare` → `recipe.json`（仅依赖图，**不含业务源** ⇒ 改代码不失效）。 |
| `builder` | `chef` | `cargo chef cook --release --locked --bin server`（依赖层，缓存命中点）→ `cargo build --release --locked --bin server` → `strip`。 |
| `runtime` | `gcr.io/distroless/cc-debian12:nonroot` | 仅 `COPY` server 二进制；非 root uid 65532；无 shell / 包管理器。 |

**为什么 distroless/cc**：server 二进制 glibc 动态链接、TLS 走 rustls+ring（ring 静态、**无 OpenSSL/
native-tls 动态依赖**），运行期只需 glibc + libgcc + ca-certificates——`cc-debian12` 恰好提供，再无多余攻击面。

## 构建

```bash
docker build -t rss-server:dev .   # 仓库根；或 make docker-build
```

`.dockerignore` 把上下文裁到「cargo 解析整个 workspace + 编 `--bin server` 子图」所需的最小集（排除
`target/`、`lints/`〔独立 workspace〕、`contracts/`〔仅 xtask codegen 输入，无 build.rs 消费〕、docs/ 等）。

## 运行：必填环境变量

server 对**缺失的必填变量 fail-fast**（启动即 `Err` 退出、错误含变量名，不静默 noop）。完整演示值见
`deploy/.env.example`。

| 变量 | 必填 | 语义 |
|------|------|------|
| `RSS_PRIMARY_LISTEN_ADDR` / `RSS_INTERNAL_LISTEN_ADDR` / `RSS_ADMIN_LISTEN_ADDR` / `RSS_HEALTH_LISTEN_ADDR` | ✔ | 4 个 listener bind 地址（`host:port`，无默认）。容器内须 `0.0.0.0:<port>` 才可经端口映射达宿主。 |
| `RSS_OIDC_ISSUER` / `RSS_OIDC_AUDIENCE` / `RSS_OIDC_TRUSTED_KINDS` | ✔ | JWT 验签 IdP；`TRUSTED_KINDS` 逗号分隔 ≥1（空则所有 JWT 401）。 |
| `RSS_OIDC_HS256_SECRET_B64URL` **或** `RSS_OIDC_ES256_SEC1_B64URL` | ✔(至少一把) | service-token HS256 / JWT ES256 公钥（base64url）。 |
| `RSS_PG_HOST` / `RSS_PG_PORT` / `RSS_PG_DATABASE` / `RSS_PG_USERNAME` / `RSS_PG_PASSWORD` | ✔ | PostgreSQL 连接参数。启动期 connect + `run_migrations` fail-fast（须有可达 PG）。 |
| `RSS_PG_SSL_MODE` | 可选 | TLS 模式（`disable`/`allow`/`prefer`/`require`/`verify-ca`/`verify-full`，大小写不敏感）。**缺省 / 非法 / 空 → `verify-full`**（零信任默认）。详见 §PG TLS。 |
| `RSS_PG_READINESS_SAMPLE_INTERVAL_SECS` | 可选 | configs_ready DB 采样周期秒（默认 5，范围 1..=300）。 |
| `RSS_OTEL_ENDPOINT` | 可选 | OTLP/gRPC trace 导出 collector 端点（**按需开启**）。**未设 → 仅 fmt 日志、不导出 trace**；`https://…` → TLS（生产默认）；`http://…` → 仅 loopback host 明文 opt-in（非 loopback / 非 http(s) scheme → **启动 fail-fast**，错误只含变量名）。详见 §可观测性导出。 |
| `RSS_AUDIT_CHAIN_KEY_B64URL` | ✔ | 审计链 HMAC key（base64url，解码 ≥32B）。缺失 / 弱 key fail-fast。 |
| `RSS_VAULT_ADDR` / `RSS_VAULT_TOKEN` | ✔ | vault secret resolver + Transit `Signer` 配置。resolver 启动期不联网（空 allowlist）；**vault `Signer` 在每次 login / refresh 时真实请求 Transit 签 access JWT（#1252）**——client 经 rustls（ring + webpki-roots，#1252 已接 TLS）加密出网，生产须**可达 vault + 有效证书链**；演示 dummy addr 下登录会因 vault 不可达 500。`ADDR` 须 `https://`（fail-fast 拒 http）。 |
| `RSS_VAULT_TRANSIT_MOUNT` | ✔ | vault Transit 引擎 mount path（如 `transit`；access JWT 签发用，#1252）。 |
| `RSS_JWT_ISSUER` / `RSS_JWT_AUDIENCE` | ✔ | 签发的 access JWT `iss` / `aud` claim（须与 `RSS_OIDC_ISSUER` / `RSS_OIDC_AUDIENCE` 一致，否则自签自验失败）。 |
| `RSS_JWT_ES256_KEY_ID` | ✔ | vault Transit sign key 名 = JOSE `kid`（验签侧据此选 `RSS_OIDC_ES256_SEC1_B64URL` 公钥；二者须运维一致接线，OIDC-ALG-KEYPATH-01）。 |
| `RSS_JWT_ACCESS_TTL_SECS` | ✔ | access JWT 有效期秒（`exp = iat + ttl`，须 > 0）。 |
| `RSS_REFRESH_TTL_SECS` | 可选 | refresh token 有效期秒（默认 30 天，须 > 0 且 ≤ 上限）。 |
| `RSS_TOPOLOGY` | ✔ | 事件传输拓扑（#1251）：`durable-shared`（per-domain AMQP，缺则回退共享 URL）/ `durable-isolated`（per-domain 必填、禁回退）。**生产 runtime 不接受 `demo`**（in-mem 不可达，启动 fail-fast）。缺失 fail-fast。 |
| `RSS_<DOMAIN>_AMQP_URL`（如 `RSS_IDENTITY_AMQP_URL`） | ✔(durable，与下行二选一) | per-domain AMQP broker URL（`amqp://user:pass@host/vhost`，**优先**于共享回退）。明文 `amqp://` 启动 warn——生产须 `amqps://`（#1565）。relay 发布 + consumer 订阅共用此 vhost。 |
| `RSS_AMQP_URL` | ✔(durable，与上行二选一) | 共享回退 AMQP broker URL：`durable-shared` 缺 per-domain 时回退此；`durable-isolated` 配此即 **fail-closed**（禁回退共享凭据）。per-domain 与 shared **至少配一个**，否则 `eventtransport::resolve` 启动 fail-closed。 |
| `RSS_REDIS_URL` | ✔(durable) | Redis 幂等去重 claimer URL（`redis://…`；明文启动 warn，生产须 `rediss://`，#1565）。 |
| `RSS_RELAY_POLL_INTERVAL_MS` / `RSS_RELAY_BATCH_SIZE` / `RSS_RELAY_SAMPLE_INTERVAL_MS` | 可选 | outbox relay 调优（默认 200ms / 16 / 30000ms）。误配 fail-soft（warn + 默认）。 |
| `RSS_REDIS_CLAIM_TTL_MS` | 可选 | Redis 幂等 claim TTL 毫秒（默认 30000；consumer 续租周期由此派生）。 |

### PG TLS（`RSS_PG_SSL_MODE`）

PG 连接 TLS 默认 `VerifyFull`（强制 TLS + 校验证书链 / 主机名，零信任）。演示 postgres 未启 TLS，故
`deploy/.env.example` 显式设 `RSS_PG_SSL_MODE=disable` 降级——**不静默**，且回退方向恒为更严：缺省 / 非法值 /
空串一律 fail-closed 回 `VerifyFull`（解析见 `runtime::parse_pg_ssl_mode`）。生产删除该行（回零信任默认）
或设 `verify-full` 并经 `PgConfig::with_ssl_root_cert` 注入私有 CA 根证书。

## 演示栈与闭环验收

```bash
make docker-smoke            # = deploy/smoke.sh：build → up → readyz 200 → 加固断言 → down -v
# 或手动：
docker compose -f deploy/docker-compose.yml up --build -d
curl -fsS http://localhost:8083/health/v1/readyz   # → 200, {"overall":"healthy", ...}
curl -fsS http://localhost:8083/health/v1/healthz  # → 200（liveness 恒 200）
curl -fsS http://localhost:8083/health/v1/metrics  # → 200, content-type text/plain; version=0.0.4（Prometheus exposition）
docker compose -f deploy/docker-compose.yml down -v
```

`deploy/smoke.sh` 机器断言四条闭环：

1. **readyz 就绪**：轮询 `/health/v1/readyz` 至 200（PG healthy + 迁移完 + 池就绪）。
2. **healthz liveness**：`/health/v1/healthz` 恒 200。
3. **metrics 导出**：`/health/v1/metrics` 200 且 content-type `text/plain; version=0.0.4`（Prometheus exposition；`PromExporter::install` 随 `run()` 必装，端点与 `RSS_OTEL_ENDPOINT` 无关）。
4. **运行时加固**：`docker inspect` 验 `User=65532:65532` 且 `ReadonlyRootfs=true`。

> **readyz 语义 / fail-closed**：`/readyz` 是所有探针的 **worst-of 聚合**——`configs_ready`（PG 池就绪，初值
> Down）· `rls_ready`（RLS 能力门）· `outbox_relay` / `event_consumer`（durable 事件 worker，#1251：worker 停
> → Unhealthy/503、relay 错误 → Degraded）。任一未就绪 → 503（fail-closed：未就绪不放流量）。裸镜像无 PG →
> 永远 503；PG/worker 就绪后转 200。`docker compose exec server sh` 不可用（distroless 无 shell，符合预期）——
> 排查用 `docker compose logs server` + `docker inspect`。

## 编排器探针（k8s）

镜像**不内置 Docker HEALTHCHECK**（distroless 无 shell，且探针应由编排器拥有）。k8s probe 指向 health
listener：

```yaml
livenessProbe:   # 进程活着即可（恒 200，不依赖 PG）
  httpGet: { path: /health/v1/healthz, port: 8083 }
  initialDelaySeconds: 5
  periodSeconds: 10
readinessProbe:  # PG/RLS + event worker（outbox_relay/event_consumer）worst-of 就绪才收流量（未就绪 503，fail-closed）
  httpGet: { path: /health/v1/readyz, port: 8083 }
  periodSeconds: 5
securityContext:           # 与镜像 / compose 加固一致
  runAsNonRoot: true
  runAsUser: 65532
  readOnlyRootFilesystem: true
  allowPrivilegeEscalation: false
  capabilities: { drop: [ALL] }
```

## 可观测性导出（Prometheus metrics + OTLP trace，#1253）

观测导出在组合根（`assemblies/runtime`）接线，**端点位置 ≠ Prometheus 默认**，必须显式配置：

### Prometheus scrape（`metrics_path` 非默认 `/metrics`）

`/metrics` 与 healthz/readyz 同挂 Health listener（8083），完整路径 **`/health/v1/metrics`**——Prometheus 默认
`scrape_path` 是 `/metrics`，**必须显式覆盖 `metrics_path`**，否则抓 `/metrics` 得 404、被记空抓取：

```yaml
# prometheus.yml scrape_config（cluster-internal Prometheus）
scrape_configs:
  - job_name: rss-server
    metrics_path: /health/v1/metrics      # 非默认 /metrics，必须显式声明
    scheme: http
    static_configs:
      - targets: ["rss-server:8083"]       # Health listener 端口；cluster-internal 可达即可
```

k8s 经 pod annotation 等价声明（Prometheus Operator / annotation-based discovery）：

```yaml
metadata:
  annotations:
    prometheus.io/scrape: "true"
    prometheus.io/path: "/health/v1/metrics"   # 同上，非默认
    prometheus.io/port: "8083"
```

**安全边界（匿名 NoAuth 面）**：Health listener（含 `/metrics`）是 `AuthScheme::NoAuth` 匿名面——**只在
loopback / cluster-internal 暴露，绝不经公网 ingress / LoadBalancer 对外**。演示栈 8083 绑 `127.0.0.1` 落实；
生产用 `ClusterIP` Service（默认集群内可达模型）+ NetworkPolicy 限定 Prometheus 命名空间访问。**不**给 Health
listener 配公网 Ingress。

### OTLP/gRPC trace 导出（`RSS_OTEL_ENDPOINT`，按需开启）

trace 导出**默认关闭**——`RSS_OTEL_ENDPOINT` 未设时仅 fmt 结构化日志（stdout），不导出 trace、零额外依赖。设置后
按 scheme 派发 typed endpoint（误配在启动接线期 fail-fast，**不静默退回 fmt**）：

| 值 | 行为 |
|----|------|
| 未设 | 仅 fmt 日志，不导出 trace（本地开发 / 无 collector 环境默认） |
| `https://collector.example:4317` | TLS（生产默认路径，tls-ring + webpki-roots） |
| `http://localhost:4317` | 明文，**仅 loopback host** 显式 opt-in（同主机 sidecar collector） |
| `http://collector.example:4317`（非 loopback 明文） | **启动 fail-fast**（零信任：明文不出本机） |
| 非 `http(s)` scheme | **启动 fail-fast** |

OTLP endpoint/TLS/insecure 是部署契约（对齐 OpenTelemetry Collector exporter 配置范式）；导出经 batch processor
后台线程，进程优雅关停时 flush 未导出 span（`ShutdownStack` 最后 drain）。

## 非 root / 只读 rootfs / 复现性

- **非 root**：runtime 基底 `:nonroot` 内置 uid 65532；compose / k8s 再显式 `user` / `runAsUser` 审计加固。
- **只读 rootfs**：server 不写盘（日志走 stdout，rustls 无磁盘状态）；compose `read_only: true` + `tmpfs:/tmp`
  兜底，`cap_drop: [ALL]` + `no-new-privileges` 证明最小权限运行。
- **复现性**：base 镜像钉 tag（`rust:1.96.0-bookworm` = 工具链 channel；`cc-debian12:nonroot`）+ `--locked`
  锁 `Cargo.lock` + `cargo-chef` 钉版。**生产硬化**：再钉 base digest（`FROM ...@sha256:<digest>`，CI 中
  `docker buildx imagetools inspect` 解析后写回）。bit-for-bit 复现（`SOURCE_DATE_EPOCH` 等）超本切片范围，
  与 SBOM/cargo-dist 同族留作 follow-up。
