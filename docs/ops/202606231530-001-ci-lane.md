# CI lane registry 与 `cargo xtask ci`

> 状态：CI 承载面已迁移到 GitHub Actions。Azure Pipelines 不再作为 RSS 的 CI 配置存在；Azure 仍可作为 active PR/Boards forge，但 PR/check 状态同步不在本 PR 范围。

## 架构

门逻辑单源在 Rust `cargo xtask`。GitHub workflow 只负责 checkout、安装工具链/工具、调用一条聚合命令；本地命令与 CI 等价。

`xtask/src/ci_lanes.rs` 是 gate ID、lane、成本、编译类型、工具要求、evidence 类型与兼容聚合资格的唯一 registry。执行参数留在 `verify.rs`，但 label、工具探测和 `--fast` 编译判定都从 registry 派生，不再维护平行字段或手工 CI 清单。

- `cargo xtask verify`: stable-only 本地快门，含 fmt、治理 meta、build、clippy、nextest、deny、dylint。
- `cargo xtask ci`: CI 超集，复用 verify 门，build/clippy 升 `--all-features --all-targets`，覆盖率门替 nextest，并追加 `public-api --check`。
- `cargo xtask integration`: 真集成 lane，通过 testkit self-provision Postgres/Redis/RabbitMQ/Mosquitto。
- `cargo xtask audit`: 定时供应链刷新 lane，跑 advisory-scoped deny + cargo-audit。

独立 lane 命令均只接受可选的 `--allow-missing-tools`；未知 flag 或尾参直接失败：

| 命令 | 内容 |
|------|------|
| `cargo xtask ci-meta` | fmt 与所有 no-compile governance gate |
| `cargo xtask ci-core` | all-features build/clippy、default nextest、backend feature tests、dylint |
| `cargo xtask ci-security` | cargo-deny + cargo-audit |
| `cargo xtask ci-coverage` | llvm-cov + public-api |
| `cargo xtask integration` | integration tests + consistency fault matrix |
| `cargo xtask audit` | deny advisories + cargo-audit nightly backstop |

`cargo-audit` 是唯一 shared gate（Security 主归属、Nightly backstop 次归属，理由为闭枚举）。`cargo xtask ci` 继续精确保留原有 41 个 gate 及顺序；Core 的 default nextest 被 Coverage supersede，因此兼容聚合不重复执行 workspace tests。

Registry 完整性由闭合 `GateId`、穷举映射和 const 唯一/完整断言在编译期证明（`CI-LANE-REGISTRY-01`）；lane taxonomy、shared 例外、兼容聚合与 ArchRules 绑定由带 synthetic red/anti-vacuity 的 `CI-LANE-PLAN-01` 守卫。

**INVARIANT CI-PIPELINE-DELEGATE-01**: `.github/workflows/ci.yml` 只调 `cargo xtask ci`，不逐条重列门命令；对应守卫在 `xtask/src/verify.rs`。

## GitHub Workflows

| Workflow | Trigger | Command | Purpose |
|----------|---------|---------|---------|
| `.github/workflows/ci.yml` | PR / push develop + PR head branch / manual | `cargo run --locked -p xtask -- ci` | 合入阻断主门 |
| `.github/workflows/integration.yml` | PR / push develop + PR head branch / manual | `cargo run --locked -p xtask -- integration` | 真后端集成测试 |
| `.github/workflows/audit.yml` | daily schedule / manual | `cargo run --locked -p xtask -- audit` | 未变依赖的新披露 CVE backstop |
| `.github/workflows/codeql.yml` | push develop / weekly schedule / manual | CodeQL init/analyze | SAST / code scanning |

## Nightly Pin

`public-api` 依赖 pinned nightly rustdoc-json。`PINNED_NIGHTLY`、`lints/rust-toolchain.toml` 和 `.github/workflows/ci.yml` 的 `RSS_NIGHTLY_PINNED` 必须一致，由 `pinned_nightly_single_source_of_truth` 守。

## Activation

仓库侧已提交 workflow。组织/仓库设置侧需要把 GitHub branch protection 配到 `develop`，至少要求 `cargo xtask ci` 与 `cargo xtask integration` 两个 PR check 通过后才能合入。若 Azure 继续作为 active PR forge，Azure PR 与 GitHub check 状态同步由仓库运营侧另行处理；本 PR 不在 `forge.sh` 中加入同步或桥接逻辑。`CodeQL` 需要启用 code scanning（private 仓需 GitHub Advanced Security），`Audit` 是定时漏洞刷新 backstop，不作为 PR required check。

本地等价命令：

```bash
make ci
make integration
make audit
```
