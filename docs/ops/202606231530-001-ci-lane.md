# Canonical execution profiles 与固定 PR Job

> 当前 GitHub Actions PR carrier 使用 selector、三个固定执行 Job 与 result-only gate。Azure 仍是
> active PR/Boards forge；仓库内 workflow 的存在不等于 Azure policy 已完成激活。

## Canonical profiles

执行成员的规范模型是闭合的 `ExecutionProfile`：

| Profile | 规范语义 |
|---------|----------|
| `check` | 只选择 primary owner 为 `check` 的静态检查与治理单元。 |
| `test` | 只选择 primary owner 为 `test` 的组件/测试单元。 |
| `integration-critical` | 只选择 primary owner 为 `integration-critical` 的关键接缝与 journey。 |
| `release-check` | 全部 primary owner 的集合并集，再按 typed subsumption 去重。 |

每个 gate、test 或 journey 只有一个 primary owner；profile membership 从 stable-ID catalog 派生，不在
workflow 或本文复制成员清单。`release-check` 使用 workspace coverage 吸收 component nextest，避免重复证明。
cargo-nextest profile 只配置 timeout、retry、JUnit 与 filter 行为，不拥有跨工具执行集合。

## PR 固定拓扑

普通 pull request 的 Job 闭集固定为：

1. `selector`：解析 base/head 差异，输出规范 `SelectionPlan`。
2. `check`：始终执行固定检查选择。
3. `test-affected`：始终存在，消费 plan 中的 affected 组件测试选择，并始终生产 producer-owned LocalOnly
   required evidence。
4. `integration-critical`：始终存在，只消费 plan 中的关键 integration unit 选择。
5. `gate`：在 `always()` 下只聚合前三个执行 Job 的最终结果。

selector 失败时，三个执行 Job 仍获得保守的 `PrComplete` 选择；gate 不解释 artifact、日志或附加回执，也不
允许任何附加文件把失败、取消或跳过改写为成功。固定 Job 名是 branch protection 的稳定边界。

`PrComplete` 是 PR 内的保守上限，只包含 PR 固定图可执行的 check、affected test 与 critical integration。
它不等于 `ReleaseCheck`，不得因此运行 workspace coverage、audit、全部 integration shard、发布或其它重型门。
`ReleaseCheck` 只由 develop、nightly、release 或显式 `cargo xtask ci full` 选择。

## Selector 语义

`ImpactSet` 是路径影响的唯一闭合模型，记录 package、反向依赖、稳定 `IntegrationUnitId`、治理路径与
unknown/high-impact/failure 状态。远端 selector 遵循以下边界：

- 普通 rename/copy 按 delete + add 计算，已知两端保持选择性；contract rename 因 owner/subscriber 语义保守
  升级 `PrComplete`。
- mixed known + unknown 保留 unknown trace，同时继续执行已知影响的定向选择；unknown-only 升级
  `PrComplete`。
- BASIS/共享基础 crate 变化使用 reverse dependency closure 投影 affected package，闭包可证明时保持选择性。
- diff、metadata、merge-base 或策略分析失败，以及真正的高影响根，升级 `PrComplete` 而不是
  `ReleaseCheck`。

SelectionPlan 必须是规范 JSON；空选择由对应固定 Job 以显式成功处理，不靠省略 Job 表示。

## 受控入口

```bash
make ci CI_BASE=origin/develop
make ci-full
cargo xtask ci run --job check --selection '<canonical SelectionPlan JSON>'
cargo xtask ci run --job test-affected --selection '<canonical SelectionPlan JSON>'
cargo xtask ci run --job integration-critical --selection '<canonical SelectionPlan JSON>'
cargo xtask ci localonly-evidence --output target/localonly-execution.json
cargo xtask ci audit
```

`make ci` 是 600 秒有界的本地 affected preflight，不运行 coverage、audit 或真实后端 integration；
`make ci-full` / `cargo xtask ci full` 是显式 `ReleaseCheck`。`ci localonly-evidence` 是 `test-affected`
required evidence producer 的唯一公开直接入口，不是独立 Job key；audit 是普通 PR 固定图外的独立命令。

精确复现 `integration-critical` 时必须复制 selector 输出的完整 canonical `SelectionPlan` JSON；不得把
`release-check` 字符串、自由 filter 或 shard 名伪装成 selection。

## L0/L1 边界

| 层级 | Canonical 入口 | 证明边界 |
|------|----------------|----------|
| Local | `make ci CI_BASE=<remote>/develop` | affected 静态证明、反向闭包 check、直接包 test/clippy；无真实后端。 |
| Full | `make ci-full` | 显式 `ReleaseCheck`，包括 workspace coverage。 |
| LocalOnly | `test-affected` 内的 producer；公开直接入口仅 `cargo xtask ci localonly-evidence --output <path>` | required evidence；exact nextest suite 成功且 active/source/executed exact-set 后原子发布报告。 |
| Live | `cargo xtask ci run --job integration-critical --selection '<canonical SelectionPlan JSON>'` | 只运行 selection 选中的真实后端 unit；缺工具或资源 fail-closed。 |

L0/L1 的具体故障语义分别见 [`../rules/consistency-l0.md`](../rules/consistency-l0.md) 与
[`../rules/localtx.md`](../rules/localtx.md)。Integration catalog 和 nextest 重放见
[`202607111214-1730-integration-shards.md`](./202607111214-1730-integration-shards.md) 与
[`202607111501-1731-nextest-test-evidence.md`](./202607111501-1731-nextest-test-evidence.md)。

## Workflow 与激活边界

`.github/workflows/ci.yml` 的结构化守卫锁定固定 Job 闭集、只读权限、selector output 传递、三个执行结果的
result-only 聚合，以及 PR 与完整事件的边界。YAML 不复制路径分类、integration catalog 或 gate inventory。

完整事件消费 `ReleaseCheck`；普通 PR 即使升级 `PrComplete` 也保持在固定图内。GitHub required-check、Azure
build validation 与 forge 切换属于运维激活状态，实际状态见
[`202607130824-1765-diff-adaptive-ci.md`](./202607130824-1765-diff-adaptive-ci.md)，不得从仓库文件存在性外推。
