# 本地 CI 租约与编译缓存

`make ci CI_BASE=origin/develop` 选择受影响 package；`make ci-full` 保留全量检查。
`CI_PART` 分为 select/checks/build/unit/consumer/amqp/kafka/providers/coverage/docs，默认 all。
本地 all 顺序执行并只持有一个槽。GitHub 单独构建 nextest archive，单元和独立消费分别执行，
AMQP、Kafka、其它 provider 最多使用三个独立 runner，组内串行；`cargo` 要求所有选中阶段成功。
详细用法和覆盖率产物见 [CI 分组与共享 fixture](202609070500-2309-ci-archive-fixtures.md)。

## 本地 target

默认使用 `~/.cache/rss-cargo-target-pool/slot-0…5`，每槽同时只属于一次 CI。槽数控制
并发 CI 数量，不设置 Cargo 编译线程数。同 worktree 活跃或全部槽忙时明确失败，避免共享
可变 target。退出后保留 sticky 产物；换 owner 才清理。无等待队列、PID 回收或 forge GC。

- `RSS_TARGET_POOL_N=6`：修改槽数；`off` 或 `0` 使用 worktree 的 `target`。
- `RSS_TARGET_POOL_ROOT=/absolute/path`：修改池根。
- 显式 `CARGO_TARGET_DIR` 绕过默认池；它与显式正数槽配置同时出现时拒绝运行。
- 直接 Cargo 不使用池；手工命令不可指向正在租用的槽。池只协调使用本入口的同用户进程，
  不构成不同权限用户之间的安全隔离。支持 macOS/Linux 本地文件系统。

锁位于 `.locks/`，元数据只描述 owner 与最近使用时间；PID 仅作诊断。构建进程继承槽锁，
主 wrapper 异常退出后仍有构建子进程时，不得清理锁或槽。取消通过整个构建进程组转发。
缩小槽数不清理活跃越界槽，后续分配会回收已空闲越界槽。

历史池必须在确认无人使用后一次性清空，重新使用原路径；本版本不导入旧 lease.json，检测到它时直接拒绝。池的版本标记为 `.rss-target-pool-v1`；
新建空根会自动初始化，未标记的非空根一律拒绝，不能把普通目录当作池清理。
日常不要删除锁文件或对正在使用的池执行清理。仓内旧 target 和 Cargo 下载缓存不在此清理范围。

## sccache

版本固定为 0.15.0。本地预先安装此版本；构建入口不联网安装。
`RSS_COMPILER_CACHE=auto|on|off` 默认为 auto：没有匹配工具时提示并使用普通 rustc；on 要求
工具与 server 可用；off 不自动接入。已有环境变量指定的 rustc wrapper 在 auto 下保留，on 报冲突。
启用时使用 `RUSTC_WRAPPER`，设置 `CARGO_INCREMENTAL=0`。编译失败不会变成缓存成功。

本地对象位于 `~/.cache/rss-sccache/objects`，socket 为同目录上级的 `server.sock`。容量采用
sccache 默认 10 GiB，可通过 `SCCACHE_CACHE_SIZE` 覆盖；修改 server 配置前应等待全部 CI 退出，
显式停止该 RSS server，再运行 CI。入口验证 server 版本与缓存目录，不停止其他正在运行的 CI。
本地统计为共享 server 累计统计，不是当前任务独占的命中数。

```sh
SCCACHE_SERVER_UDS="$HOME/.cache/rss-sccache/server.sock" sccache --show-stats
# 仅在没有活跃 CI、需要更新 server 配置时执行：
SCCACHE_SERVER_UDS="$HOME/.cache/rss-sccache/server.sock" sccache --stop-server
```

完整 target 热复用与编译对象命中是不同证据。缓存命中由 sccache 根据源码、参数、工具链等判断，
不保证链接阶段、所有 check 或跨 worktree 编译都命中。普通与覆盖率编译参数不同；不全局改写路径。

## GitHub

checks 执行三种 feature check、Clippy 和独立 doctest 命令；只有 develop/显式 full 增加 deny；SemVer 按兼容承诺与影响独立选择、执行。
全工作区回退和 full 统一插桩构建一次；affected 构建不插桩。每个编译 job 独立 target 和 sccache server，
保留行号调试信息、原 Cargo 并行配置及 native compiler cache，不缓存完整 target。

Cargo cache 只包含 registry index/cache 和 git db；checks/build/consumer 分别保存不可变快照。
两类 key 均含格式版本、OS/架构、工具链、输入 hash 与唯一 run/attempt；编译缓存另含 sccache 版本、
分组和插桩身份。PR 只恢复，develop/dispatch 仅在对应执行成功后保存。`warm_run=ID-attempt` 要求
同 SHA 的成功 dispatch，三组必须精确命中指定缓存，不允许回退后冒充热跑。
消费方 metadata 验证使用 rustc 报告的当前宿主进行 `--filter-platform`，不为验证主动下载
Android 等其他平台依赖。Cargo.lock 中第三方库的平台条件记录不构成本项目的平台支持承诺。
恢复进程测试等待持久化 converged 状态并受原调用预算约束，不把固定 100ms 运行窗口当作
收敛证明；AMQP 资源关闭取消覆盖孤儿 replacement 清理，每代 transport 共享一次关闭及其结果，
关闭预算保持不变。Saga 的 COMMIT 回执丢失验证使用默认 lease，确认丢失后由夹具显式过期，
避免 300ms 租约与 CI 调度竞争，也不再用固定 sleep 猜测接管时机。

恢复失败后丢弃本次部分恢复，正常冷构建；保存失败不覆盖检查结果。编译对象在统计与 server
停止后保存；取消或目录异常不保存。日志包含命中统计、恢复 key、目录大小、磁盘余量和运行耗时。
默认仓库总 cache 额度与每个 runner 的本地磁盘是不同预算，多代快照可能被服务端淘汰。
