# CDC Outbox / Debezium Runbook

适用范围：Postgres `outbox_log` append-only CDC mode，经 Debezium PostgreSQL connector + Outbox EventRouter 发布到 Kafka topics。

## 选择 Relay 还是 CDC

- **Relay mode** 是 RSS 默认路径：`PgInfraDeps::emitter(clock)` 写 mutable `outbox`，由 RSS relay worker 发布到 AMQP/MQTT/memory transport，并负责 retry、DLX、readyz 与 tenantAuthority header。
- **CDC mode** 是显式 opt-in 路径：`PgInfraDeps::cdc_emitter(clock)` 写 append-only `outbox_log`，由 Debezium 从 Postgres WAL 捕获并路由到 Kafka。该模式不读取 `outbox`，也不回退到 relay。
- 同一 producer wiring 只能选择一种 emitter。不要双写 `outbox` 与 `outbox_log`，否则消费者会看到重复事实且两条链路的 DLX/重试语义不同。

## 生成 Connector Skeleton

```bash
cargo xtask cdc-config debezium > /tmp/rss-outbox-log-debezium.json
```

输出是 Kafka Connect REST body skeleton：

- 只包含 `${RSS_CDC_*}` 占位符，不包含真实 host、用户名或密码。
- 捕获表固定为 `public.outbox_log`。
- `publication.autocreate.mode=disabled`，要求 DBA 预先创建 publication。
- `snapshot.mode=no_data`，避免首次启动把历史 `outbox_log` 全量重放进 Kafka。
- Outbox EventRouter alias 固定为 `outbox`，所有 SMT 参数均使用 `transforms.outbox.*` 前缀。
- 只有 `${RSS_CDC_*}` 是部署占位符；EventRouter topic routing 使用 Java regex replacement `$1`，避免被通用环境变量替换器误处理。

提交前用部署系统替换占位符，或用 Kafka Connect 支持的 config provider 解析环境变量。不要把替换后的凭据文件提交到仓库。

## Required Database Setup

Debezium 用户应是专用复制用户，最小权限：

- `REPLICATION` 权限，用于读取 logical replication slot。
- `SELECT` on `public.outbox_log`。
- 使用 `pgoutput` 时，publication 已存在，因此不需要 connector 自动建 publication。

DBA 示例：

```sql
CREATE PUBLICATION rss_outbox_log_pub FOR TABLE public.outbox_log;
```

对应占位符：

```text
RSS_CDC_PUBLICATION_NAME=rss_outbox_log_pub
RSS_CDC_SLOT_NAME=rss_outbox_log_slot
```

不要授予 Debezium 用户 `UPDATE` 或 `DELETE` on `outbox_log`。该表仍是 append-only ledger，应用写入角色也只持 `SELECT, INSERT`。

## EventRouter Mapping

`cargo xtask cdc-config debezium` 输出的核心映射：

| Debezium field | RSS column | Meaning |
|---|---|---|
| `table.field.event.id` | `event_id` | Event identity；EventRouter 自动写入 Kafka header `id`。 |
| `table.field.event.key` | `event_id` | Kafka record key；避免把 persisted-only subject/aggregate identifier 暴露到 broker key。 |
| `table.field.event.payload` | `payload` | Reviewed event payload bytes。 |
| `route.by.field` | `topic` | 输出 Kafka topic 等于 RSS topic。 |

Additional placement:

```text
tenant_id:header:tenantId,
contract_version:header:schemaVersion,
schema_hash:header:schemaHash
```

不配置 `:partition`。Debezium EventRouter 的 partition placement 读取 `Int32` 字段，RSS 没有这样的物理列。

不把 `aggregate_id` 配置为 Kafka record key。CDC writer 当前把 `EnvelopeSubjectId` 写入 `outbox_log.aggregate_id`，它和 `subjectId` 一样属于 persisted-only identity，不进入 broker key/header/user property。默认 skeleton 使用 `event_id` 作为 key；若部署需要 per-aggregate Kafka partition affinity，必须先设计 reviewed CDC partition key（例如专用 non-sensitive key 或 HMAC digest）并同步 migration、writer 和测试。

不配置 `table.field.event.schema.version`。Debezium EventRouter 读取该字段为 `Int32` schema version，RSS `contract_version` 是 `vN` 字符串；schema version/hash 通过 header 暴露。

不默认配置 `table.field.event.timestamp`。`created_at` 是 Postgres `timestamptz`，Debezium PostgreSQL connector 可能把它暴露为 zoned timestamp 字符串，而 EventRouter timestamp override 只接受 Kafka Connect timestamp/int64 类字段；默认让 EventRouter 使用 Debezium source event timestamp。只有在当前 Debezium/Postgres mapping 已经验证该列是受支持 timestamp 逻辑类型时，才可在部署侧手工追加：

```json
"transforms.outbox.table.field.event.timestamp": "created_at"
```

不把 `metadata` 或 `causation_id` 放入 header。RSS broker-visible header 只允许 transport-safe metadata；CDC path 的业务/诊断 persisted-only 字段留在 outbox log 和下游 envelope 中处理。

不配置 `:envelope` additional placement。默认 Kafka value 保持为 `payload` bytes；`contract_id`、`aggregate_type` 等 persisted fields 不混入 EventRouter value envelope。若后续要发布 envelope value，应作为独立 CDC message shape 设计，并指定匹配的 converter。

## Payload Converter Boundary

`outbox_log.payload` 是 `bytea`，RSS 只保证它是已审查的事件 payload bytes。Kafka Connect worker 的 value converter 由部署环境决定：

- 默认按 bytes 处理，例如使用 Kafka Connect 的 bytes/byte array converter，或在 sink 侧按 RSS contract 解码。
- JSON converter 不会自动把 Postgres `bytea` payload 解析成 JSON object；若部署要求 Kafka value 是 JSON object，必须先设计并验证 bytea-to-JSON 的显式转换路径。
- 若部署使用 Avro/Protobuf envelope，converter 和 schema registry 配置属于 Kafka Connect 平台配置，不由 xtask 输出真实地址或凭据。

不要在 runbook 或 skeleton 中写真实 schema registry URL、用户名、密码或 token。

## Replay And Recovery

- `snapshot.mode=no_data` 是默认安全值。若需要重放历史 `outbox_log`，先在隔离 consumer group / topic 前缀中演练，确认下游幂等。
- 不要删除 active replication slot。slot 丢失会造成 WAL 位置丢失，恢复时需要人工决定从新 snapshot 还是从备份点重建。
- Kafka topic 重放必须按 `event_id` 幂等；`aggregate_id` 只提供 per-aggregate key affinity，不是全局去重键。

## Local Validation

```bash
cargo xtask cdc-config debezium | jq .
cargo test -p xtask cdc_config
```

如果 `jq` 不存在，可直接用 `cargo test -p xtask cdc_config` 校验 renderer 输出的 JSON 结构、占位符和禁止项。
