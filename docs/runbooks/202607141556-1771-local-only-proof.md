# LocalOnly proof registry 与 receipt coverage

本 runbook 说明如何读取 active LocalOnly registry、静态 effect proof 与源码登记的 runtime
conformance receipt。receipt 缺失与 provenance 违规都会阻断验证；源码登记不被
解释为本次测试已经执行。

## 静态诊断与运行证据

```bash
./hack/cargo.sh xtask consistency local-only-effects
./hack/cargo.sh xtask consistency report --format json > consistency-posture.json
./hack/cargo.sh xtask consistency report --format markdown > consistency-posture.md
cargo xtask ci localonly-evidence --output target/localonly-execution.json
```

静态 consistency JSON 仅输出 schema v4。调用方必须同时检查命令退出码并完整解析 JSON；当前 CI 不生成或上传
这份静态报告，人工留存或转交时也不得使用采集、provenance、结构或序列化失败留下的截断输出。前两类命令只
提供静态 posture/source registration；最后一条才执行从同一 typed inventory 派生的 exact nextest suite，
并只在全部成功且集合对账后发布 strict schema v2 runtime report。`consistency report` **不是**新的 enforcement
carrier：静态 source receipt 与 runtime execution evidence 严格分离；阻断 verdict 仍由 `local-only-effects` gate 给出。

## 闭包规则

active LocalOnly **exact-set** 的唯一 owner 是 compiled `generated::http::LOCAL_ONLY_SPECS`；codegen
从 manifests 同源生成该表，并与 source receipt contract ID 做 typed exact-set 对账。集合必须非空，
missing、extra、duplicate 或 equal-count-wrong-set 均 fail-closed。scanner 不解析 generated Rust 源码
镜像或 filesystem registry walk 重建第二份 exact-set；manifest 用于声明发现，但不是 scanner exact-set
的唯一真源。Cargo package/path/target/direct-dependency facts 只经 command-scoped `WorkspaceFacts`
注入。进程内 correctness cache upsert/remove 不算 business effect。文档不维护 receipt 实例清单。

LocalOnly 的三维 runtime observer 是 `BusinessWrite` / `Outbox` / `Publish`，对应计数键为
`business_writes` / `outbox` / `publishes`。零增长证明 handler/domain 没有业务持久化、业务 outbox 或直接
publish；correctness cache、metrics/trace、auth security audit 等 operational state 继续走专门治理，
provider-owned read-path transaction 保持允许。PostgreSQL `tenant_scoped_read*` 当前通过 transaction 绑定
tenant context；该 helper 不宣称 PostgreSQL `READ ONLY` 或稳定 snapshot。

运行 anti-vacuity 要求 active/source/executed 三个 typed ID 集合非空且彼此精确相等，同时 exact test
filter 非空。是否在某次 revision 上真实执行，必须以该次 `ci localonly-evidence` 的 strict schema v2
报告为准，不从数量或文档清单推导。

## 证据强度与失败语义

- **Hard 上游**：codegen 只为 active LocalOnly route 生成专用 conformance marker，并生成 compiled
  `LOCAL_ONLY_SPECS`；route 失活或改为非 L0 时 canonical marker 消失，receipt callsite 编译失败。
- **Medium 下游 residual**：xtask 对每个 canonical site 闭合 marker、`SPEC` ID、mounted `ROUTE`、
  production mount、state/port/auth/privilege、receipt namespace 防伪造、三维 observers 的 API /
  record mutation provenance，以及 Rust module/cfg/macro reachability；再与 compiled exact-set 对账。
  decoy/bait、错 route/path/method/provider、cfg/sibling bait、空或 wrong-but-finalized routes 均拒绝。
  已退役：provider helper lineage、字段字面量、helper pairing、fixed site count、局部顺序 / source bait；
  **不再**声称 Identity aggregate production lineage 或 Settings provider→service→Domain mounted lineage。
- receipt 仅能在完整 operation await 后的 `BusinessWrite`/outbox/publish post-check 成功时由 testkit 铸造；字段和
  构造器不公开。runner-owned 私有目录仅接受 post-check 成功后写入的 strict v1 marker。
- `ci localonly-evidence` 必须同时取得 nextest 全部成功的私有能力与 active/source/executed exact-set 的私有能力，
  report publisher 才可构造。missing、extra、duplicate、malformed、symlink、stale marker、wrong job/revision
  与 equal-count-wrong-set 均 fail-closed；不接受旧 schema、别名、JUnit 或 count-only 推导。
- duplicate、unknown、stale、marker/ID 错配、alias/wrapper、裸字符串、隐藏执行上下文、未 fail-loud
  解包或未用 `::core::assert_eq!` 断言 receipt 属于 provenance 错误并 fail-closed；缺 receipt 同样产生
  `MissingLocalOnlyReceipt`，阻断 `local-only-effects` / affected `make ci` 并令 schema v4 report `status=failed`。

该 Medium 源码证书仍只说明 canonical conformance test site 的源码闭合存在，不能说明当前 xtask 调用执行过该
测试，也不是 syscall、网络、文件系统或后台任务 sandbox。affected `make ci` 或显式 direct gate 只保留静态证明；完整 `verify`
与 `ci localonly-evidence` 复用同一执行 runner。报告证明受控跨进程 marker 集合在本次 suite 中闭合，仍诚实定级
Medium，不把端到端运行事实虚报为 Hard。

## 数据与安全边界

- **Static consistency v4**：仅包含 canonical contract ID、静态闭合状态、计数和 workspace-relative
  mount source；它不携带本次执行事实。
- **Runtime execution v2**：必须包含固定 owner `job=test-affected`、`sourceRevision`，以及排序后的 `activeContractIds`、
  `sourceReceiptContractIds`、`executedContractIds` 三个数组；不得省略 revision identity 或退化为
  count-only 证据。

两类报告都不得包含 tenant、subject、device、请求/响应、payload、provider 错误文本、时间、主机、绝对路径
或其他敏感数据。runtime v2 的 `sourceRevision` 是绑定被执行源码所必需的 revision identity。
