# LocalOnly proof registry 与 receipt coverage

本 runbook 说明如何读取 active LocalOnly registry、静态 effect proof 与源码登记的 runtime
conformance receipt。合法的 receipt 缺失不改变静态 CI verdict；provenance 违规仍阻断验证。源码登记不被
解释为本次测试已经执行。

## 生成证据

```bash
./hack/cargo.sh xtask consistency local-only-effects
./hack/cargo.sh xtask consistency report --format json > consistency-posture.json
./hack/cargo.sh xtask consistency report --format md > consistency-posture.md
```

JSON 仅输出 schema v2。调用方必须同时检查命令退出码并完整解析 JSON；采集、provenance、结构或
序列化失败时不得上传可能截断的 artifact。

## 当前基线

active LocalOnly 集合由 codegen 从 active HTTP contract manifests 派生为
`generated::http::LOCAL_ONLY_SPECS`，当前为 6 条。源码可发现 receipt 当前登记 2 条：

- `audit.list-entries`
- `identity.profile`

以下 4 条保持 `missing`，由后续 route conformance 子任务补齐：

- `identity.policies-get`
- `identity.policies-list`
- `identity.roles-list`
- `settings.config-get`

`missing` 是 report-only coverage 状态，不是静态 posture finding，不会令
`consistency local-only-effects` 或 report 顶层静态 `status` 失败。

## 证据强度与失败语义

- **Hard 上游**：codegen 只为 active LocalOnly route 生成专用 conformance marker，并生成 active
  registry；route 失活或改为非 L0 时 canonical marker 消失，receipt callsite 编译失败。
- **Medium 下游**：xtask 对每个 canonical site 闭合同一 generated module 的 marker、`SPEC` ID、mounted
  `ROUTE` typed proof、直属三维 observers、同一词法模块 `self::factory` 内“同一 routes 先 proof 后 finalize 并
  tuple 返回”的 router/proof，以及 direct generated GET operation；decoy/bait、错 route/path/method/provider、
  cfg/sibling bait、空或 wrong-but-finalized routes 均拒绝，再与 active exact-set
  对账。
- receipt 仅能在完整 operation await 后的 write/outbox/publish post-check 成功时由 testkit 铸造；字段和
  构造器不公开。
- duplicate、unknown、stale、marker/ID 错配、alias/wrapper、裸字符串、隐藏执行上下文、未 fail-loud
  解包或未用 `::core::assert_eq!` 断言 receipt 属于 provenance 错误并
  fail-closed；单纯缺 receipt 只进入报告。

该 Medium 证书仍只说明 canonical conformance test site 的源码闭合存在，不能说明当前 xtask 调用执行过该测试，也不是
syscall、网络、文件系统或后台任务 sandbox。真实测试结果仍以对应 crate test/CI lane 为准。

## 数据与安全边界

报告仅包含 canonical contract ID、闭合状态、计数和 workspace-relative 静态 mount source。不得加入
tenant、subject、device、请求/响应、payload、provider 错误文本、时间、主机、Git SHA 或绝对路径。

## 未来切换 fail-closed

只有在 6/6 route 均有真实 conformance、这些测试进入受控 full verify/CI 执行面、并有执行 artifact 或等价
机器证据后，才能用独立变更把 `missing` 接入 blocking finding。禁止通过时间、环境变量或隐式阈值自动
ratchet；切换时必须更新 schema、门语义、synthetic red、anti-vacuity 与本 runbook。
